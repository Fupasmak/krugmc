# Сквозная проверка руками

Порядок проверки всего, что связано с входом, голосованием и завозами.
Занимает минут двадцать. Всё делается на локальной машине или на VDS.

## Что нужно подготовить

1. PostgreSQL поднят, `npm run db:migrate` и `npm run db:seed` отработали.
2. В `.env` заполнены `SESSION_SECRET`, `MC_HMAC_SECRET`, `INTERNAL_API_SECRET`,
   `TG_BOT_TOKEN`.
3. Запущены сайт (`npm run dev`) и бот (`npm run dev:bot`).
4. Бот — администратор канала `@serverKRUG`.
5. Сервер Paper с установленным плагином, в `plugins/KRUG/config.yml`
   прописан тот же `api.secret`, что и `MC_HMAC_SECRET`, а `api.url` смотрит
   на сайт (для локальной проверки — адрес машины в сети, не `localhost`,
   если сервер на другом компьютере).

Проверка живости:

```bash
curl http://localhost:3000/api/health
curl http://localhost:8081/health
```

## 1. Вход через Minecraft

1. Открой `/login` → «Получить код». Появится код и команда.
2. В игре напиши `/krug login КОД`.
3. **Ожидаемо:** в игре «Вход подтверждён», вкладка сама уходит на `/me`.
4. В шапке появилась квадратная голова твоего скина и ник.

Отдельно проверь ошибки:

| Что сделать | Ожидаемо |
|---|---|
| Ввести чужой или выдуманный код | «Код не найден или уже использован» |
| Подождать 5 минут и ввести код | «Код истёк» |
| Ввести один и тот же код дважды | второй раз — «Код не найден» |
| Испортить `api.secret` в конфиге плагина, `/krug reload`, повторить вход | в игре ошибка, в логе сайта `bad_signature` |

## 2. Вход через Telegram

1. В другом браузере (или в режиме инкогнито) открой `/login` →
   «Войти через Telegram». Откроется бот.
2. Нажми в боте «Подтвердить вход».
3. **Ожидаемо:** вкладка сайта входит сама, в шапке имя из Telegram.
4. Нажми в боте «Отмена» на новой ссылке — вход не происходит.

## 3. Привязка Telegram к аккаунту игрока

1. Зайди как игрок → `/me` → «Привязать Telegram».
2. Подтверди в боте.
3. **Ожидаемо:** на `/me` написано «Telegram привязан: @ник».
4. Нажми «Отвязать» — статус вернулся.
5. Попробуй привязать тот же Telegram, которым уже вошёл зритель из пункта 2 —
   **ожидаемо** отказ «Этот Telegram уже используется как аккаунт зрителя».

## 4. Добавление завоза

1. Под игроком нажми `[+]` в шапке (золотой блок).
2. Заполни заголовок, текст, выбери метку, приложи картинку и видео.
3. **Ожидаемо:** полоса отправки, переход на страницу завоза, вложения видны,
   видео проигрывается и перематывается.
4. Проверь лимиты: файл больше 5 МБ (картинка) или 200 МБ (видео) — отказ до
   отправки; пятый файл добавить нельзя.
5. Зайди зрителем (Telegram) и открой `/posts/new` — **ожидаемо** редирект,
   кнопки `[+]` в шапке нет.

## 5. Правка и удаление завоза

1. На своём завозе нажми «Править», измени текст, сохрани.
2. **Ожидаемо:** внизу карточки появилась еле заметная подпись «изменено …».
3. Нажми «Удалить» → «Точно удалить». Завоз пропал из ленты.
4. Под админом: `/admin/posts` → «Вернуть». Завоз снова в ленте.

## 6. Голосование

### Неподписанный зритель

1. Войди через Telegram аккаунтом, **не подписанным** на канал.
2. Нажми «+» на чужом завозе.
3. **Ожидаемо:** сообщение про подписку с кнопками «Подписаться» и
   «Я подписался, проверить». Голос не засчитан.
4. Подпишись на канал, нажми «Я подписался, проверить» —
   **ожидаемо** «Подписка найдена».
5. Нажми «+» ещё раз — голос проходит.

### Повторный голос

6. Нажми «−» на том же завозе.
7. **Ожидаемо:** кнопки заблокированы, выбранный «+» подсвечен, всплывает
   «Голос уже отдан. Изменить или отменить его нельзя.»
8. Проверь через API, что второй голос действительно не прошёл:

```bash
curl -i -X POST http://localhost:3000/api/posts/<id>/vote \
  -H 'Content-Type: application/json' \
  -H "X-CSRF-Token: <значение cookie krug_csrf>" \
  -b 'krug_session=<токен>; krug_csrf=<токен>' \
  -d '{"value":-1}'
```

**Ожидаемо:** `400` и `{"ok":false,"error":"already_voted"}`.

### Игрок и автор

9. Зайди игроком и нажми «+» — **ожидаемо** «Голосуют только зрители из Telegram».
10. Под зрителем нажми «+» на завозе, где он же автор (если такой случай есть) —
    **ожидаемо** «За свой завоз голосовать нельзя».

### Бот выключен

11. Останови бота, попробуй проголосовать новым зрителем —
    **ожидаемо** «Бот сейчас недоступен…», голос не засчитан.

## 7. Игроки и карточки

1. `/admin/players` → добавь игрока с ником, которого ещё нет.
2. Загрузи ему карточку PNG. Проверь `/players` — карточка на месте.
3. Зайди на сервер этим ником и подтверди вход через `/krug login`.
4. **Ожидаемо:** новая запись не появилась, у существующей проставились UUID,
   дата первого входа и голова скина; карточка осталась прежней.
5. Смени скин в Minecraft, войди ещё раз — голова на сайте обновилась
   (может понадобиться обновить страницу: у картинки кэш 5 минут).

## 8. Архив, медиа, тексты

1. `/admin/archive` → создай неделю, добавь постройку с файлом и видео ссылкой.
2. Поставь неделю «Опубликована» — она появилась на `/archive` и на главной.
3. `/admin/media` → добавь ролик YouTube, проверь `/media` и страницу автора.
4. `/admin/content` → поправь текст «Что такое KRUG», сохрани, открой `/about`.
5. Нажми «Вернуть текст из файла» — вернулся черновик из `web/content`.

## 9. Права

| Кто | Что проверить |
|---|---|
| Гость | `/admin`, `/me`, `/posts/new` уводят на вход или главную |
| Зритель | `/admin` уводит на главную, кнопки `[+]` нет |
| Игрок без роли | `/admin` уводит на главную |
| Админ | `/admin` открыт, роли раздавать нельзя |
| Fupasmak | `/admin/players` — кнопка роли переключает «игрок/админ» |

## 10. Адаптив и мелочи

1. Ширина 360px: шапка сворачивается в меню-инвентарь, ничего не уезжает вбок.
2. Планшет 768px и десктоп — сетки перестраиваются, горизонтальной прокрутки нет.
3. `/чего-нибудь-нет` — страница «Чанк не прогрузился».
4. `/robots.txt` и `/sitemap.xml` открываются.
5. Открой страницу Zero Season — блоки левитируют; при включённом в системе
   «уменьшении движения» анимация стоит.

## 11. Безопасность (быстрая проверка)

```bash
# запрос без подписи
curl -i -X POST http://localhost:3000/api/plugin/mc-login \
  -H 'Content-Type: application/json' -d '{"code":"ABC123"}'
# ожидаемо 401 missing_signature_headers

# повтор подписанного запроса с тем же nonce
# ожидаемо второй раз 401 nonce_reused

# мутация без CSRF-заголовка
curl -i -X POST http://localhost:3000/api/auth/logout -b 'krug_session=<токен>'
# ожидаемо 403
```

Также проверь, что в тексте завоза `<script>alert(1)</script>` выводится как
текст, а не выполняется, и что ссылки в завозах получают `rel="nofollow ugc"`.
